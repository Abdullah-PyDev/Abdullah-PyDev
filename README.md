## About

I build software at the intersection of language models and real business problems — the kind that doesn't stay a demo, but ends up doing actual work: reading documents, retrieving the right context, remembering what happened three turns ago.

Most of what I spend time on sits between *"the model works in a notebook"* and *"the product works in production"* — retrieval pipelines, semantic memory, and increasingly, systems where an agent has to decide something, not just respond to a prompt.

I'd rather ship something small that's actually relied on than something impressive that stays a prototype. The interesting problems in AI engineering right now aren't "can I call the API" — they're retrieval quality, failure handling, and what happens when the model is wrong.

## Projects

**MemoAI** — an AI-powered PDF assistant that remembers.
Most document-QA tools treat every question in isolation and re-embed the same context on every turn. MemoAI holds conversational state across a session, so a follow-up question like *"what about the section before that?"* resolves correctly instead of losing the thread. The interesting problem wasn't the retrieval — it was designing memory that stays cheap and fast as a conversation grows.
<br/>`FastAPI` `Streamlit` `Sentence Transformers` `Gemini API`

**ANN Research** — a neural network with no framework underneath.
Forward and backward propagation implemented directly in NumPy, with no autograd. The point wasn't to build something production-ready — it was to remove the abstraction and confirm I understand what a training loop is actually doing before trusting a framework to do it for me.
<br/>`Python` `NumPy`

<sub>Also building: a voice-based phone ordering agent for restaurants (early stage, not yet public) and a marketing site for a software studio (DSLogics).</sub>
